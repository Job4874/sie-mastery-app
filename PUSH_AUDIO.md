# Regenerating and pushing the audio files

`static/audio/` contains the pre-generated voice clips: the welcome clip plus the
8 curriculum lessons — **15 clips of WAV**, listed with exact byte sizes in
`static/audio/manifest.json`. The app plays these saved files before any live TTS.

Regenerate them from the lesson text with the torch-free composer:

```powershell
pip install -r requirements.txt

# one-time voice download (~119 MB, git-ignored)
curl -L -o models/kokoro-v1.0.int8.onnx https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.int8.onnx
curl -L -o models/voices-v1.0.bin https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin

python tools/compose_audio.py --list
python tools/compose_audio.py --force
```

The composer reads `UNITS[].lesson` straight out of `static/index.html`, writes
24 kHz mono PCM WAVs, and updates `manifest.json` with the new byte sizes and
durations. Use `--only lesson-3-debt --force` to rebuild one clip.

Git handles the binaries natively. From a normal clone on your PC:

```powershell
git clone https://github.com/Job4874/sie-mastery-app.git
cd sie-mastery-app
python tools/compose_audio.py --force
git add static/audio
git commit -m "Regenerate lesson voice clips"
git push
```

`tools/verify.py` and the GitHub Actions compile-check confirm that every clip in
`manifest.json` exists and matches its recorded byte size. New dynamic clips
generated by `/api/tts` land in `tts_cache/` and are not committed.

The older `lesson-*.mp3` files are legacy short clips and are not referenced by the
manifest or the app; the current build uses the WAV lesson files.
